Build a professional, simple, and responsive Quiz Application with a Timer.

Requirements:

1. Quiz Questions
- Store multiple-choice questions with 4 options each.
- Each question must have exactly one correct answer.
- Start with at least 10 sample questions.
- Keep the question data easy to edit or replace later.

2. Quiz Interface
- Show one question at a time.
- Display 4 multiple-choice options as clean clickable cards/buttons.
- Allow the user to select one option and submit it.
- Clearly show the current question number, e.g. Question 3 of 10.
- Add Previous and Next/Submit controls where appropriate.

3. Timer
- Give each question a 30-second timer.
- Display the remaining time clearly.
- The timer must count down every second.
- When the timer reaches 0, automatically mark the question as unanswered/incorrect and move to the next question.
- Do not allow the timer to become negative.

4. Score
- Track the user's score automatically.
- Give 1 point for each correct answer.
- Do not allow multiple submissions for the same question.

5. Result Screen
- After all questions, show:
  - Final score
  - Total questions
  - Correct answers
  - Incorrect answers
  - Unanswered questions
  - Percentage
- Add a "Restart Quiz" button.

6. Design
- Use a clean, modern, professional UI.
- Keep the design simple and suitable for a college project.
- Use good spacing, readable typography, cards, buttons, and subtle animations.
- Make it fully responsive for laptop and mobile screens.
- Show clear visual feedback for selected, correct, and incorrect answers.
- Do not overcomplicate the interface.

7. Code Quality
- Use a clean component-based structure.
- Keep quiz data, timer logic, scoring logic, and UI properly organized.
- Validate all user interactions.
- Make sure there are no console errors.
- Test the complete flow: Start → Answer → Timer → Next → Result → Restart.

Important:
The application should be fully functional, not just a visual mockup. Preserve the existing project structure where possible and avoid unnecessarily deleting or replacing working files.
